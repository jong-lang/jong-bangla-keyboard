## Composition model

The engine stores the raw keystrokes for the active word. It derives the Bangla
output from that buffer and exposes the converted preedit to the platform adapter.

**Preedit** is the current, uncommitted text shown in the application. **Commit**
means inserting the converted Bangla output into the application's document.
Before commit, Backspace edits the raw input and recomputes the whole active word.
After commit, ordinary document editing belongs to the application; v1 does not
promise to recover raw keystrokes from already committed Bangla.

**Confirmed on 2026-10-29:** Ctrl+Backspace discards the entire active raw
buffer and consumes the key. With no active input, it reaches the application
for normal word deletion. This includes an active buffer whose converted output
is empty, such as an escape: activity is determined by raw input, not visible text.
A repeated Ctrl+Backspace after clearing the buffer can therefore reach the app.

Space and Enter commit the converted output, then forward the same key exactly
once; Enter can insert a newline or send a message according to the application.
This replaces the earlier proposal to consume the first Enter. Punctuation stays
in the raw buffer until Space, Enter, or another explicit commit. This keeps
multi-key punctuation and escapes editable: periods can become an ellipsis,
and a backtick can change the preceding symbol. Ctrl+Backspace clears all such
pending input together; it does not attempt application-style punctuation-based
word segmentation inside the buffer.

## Composition controller API

Implemented on 2026-10-29 in [composition.rs](../src/composition.rs), with
independent regression sequences in [tests/composition.rs](../tests/composition.rs).
Converted expectations use the already reference-checked rule behavior; editing
and key-forwarding expectations come from this project's user-confirmed contract,
not from the upstream parser.
The public `Composition` type owns a raw UTF-8 buffer and its converted preedit;
it has no candidate selection, document history, desktop events or global state.
It recomputes with the existing `transliterate` function after each edit.

| Operation | State/output contract |
| --- | --- |
| `new()` / `default()` | Empty, inactive controller |
| `is_active()` | True when raw input exists, even if preedit is empty |
| `preedit()` | Borrow the converted output; no raw-input accessor |
| `insert(char)` | Append one non-whitespace, non-control Unicode scalar and recompute; return true |
| Rejected `insert(char)` | Return false without changing state; adapter handles boundaries/shortcuts separately |
| `backspace()` | Pop one raw Unicode scalar, recompute, and return true; false only when inactive |
| `delete_word()` | Discard the whole active buffer without a commit; return whether raw input existed |
| `commit()` | Clear state and return `Some(converted output)`; `None` only when inactive |
| `cancel()` | Discard state without a commit; return whether raw input existed |
| `reset()` | Unconditionally discard state without a commit |
| `handle_key(CompositionKey)` | Return `KeyEffect { consumed, committed }` using the confirmed key table below |

Each accepted Unicode scalar is one editable input unit; Backspace never removes
a byte of Bangla output. Combining characters are separate raw units. Physical
key translation and multi-character input events belong to the adapter, not this
API. `insert` accepts punctuation, digit keys and unmatched Unicode without
adding boundaries. Whitespace and control characters cannot enter the raw buffer;
a rejected insertion is not permission to forward an event while leaving active
composition behind. The adapter must apply its explicit boundary/shortcut policy.

| Normalized `CompositionKey` | Active raw input | No active input |
| --- | --- | --- |
| `Backspace` | Remove one raw scalar; consume; no commit | Forward; no commit |
| `CtrlBackspace` | Clear the entire raw buffer; consume; no commit | Forward; no commit |
| `Space` | Commit, clear state, then forward Space | Forward Space |
| `Enter` | Commit, clear state, then forward Enter | Forward Enter |

The adapter publishes the resulting preedit, sends any nonempty committed output,
then forwards the original key exactly once if `consumed` is false. It must not
insert a second space or newline itself. `Some("")` is a real finalized composition
with empty output; skip the framework's empty commit but preserve key handling.
For example, raw o-backtick is active with empty preedit: Backspace restores অ,
Ctrl+Backspace consumes deletion, and Enter finalizes it and still reaches the app.

Use one controller per input context. `reset()` provides a cleanup operation;
it does not choose whether lifecycle events should commit first. The adapter
applies the [interaction contract](adapter-contract.md#adapter-interaction-contract).
No raw or committed input is logged or persisted; the
controller and its text-bearing result omit Debug formatting. Desktop coverage
remains bounded to the recorded smoke evidence; core batch timings are recorded
in the [resource measurement](performance.md#local-resource-measurement-and-leak-check), with
frontend event latency still unmeasured.

## Proposed architecture

1. **Transliteration core (Rust):** deterministic raw-input-to-Bangla conversion;
   no knowledge of Fcitx5, IBus, TSF, macOS, display servers, dictionaries or UI.
2. **Composition controller (Rust, implemented):** raw buffer, converted Bangla
   preedit, editing, and explicit commit/cancel/reset actions.
3. **Fcitx5 adapter (local experiment implemented):** translates framework events
   into controller actions and sends preedit/committed text to Fcitx5. Desktop
   validation and packaging remain separate.
4. **IBus adapter (source-build experiment implemented):** C11/GLib service
   reusing the shared Rust C ABI, with private D-Bus and staged-install checks.
   Initial [GNOME Wayland VM smoke evidence](ibus.md#gnome-vm-smoke-result) is
   recorded; full desktop acceptance remains incomplete.
5. **Windows TSF and macOS adapters (planned):** reuse the Rust behavior
   through native event/ownership boundaries, following the [roadmap](roadmap.md#architecture-boundaries).
6. **Distribution (planned):** native packages and platform installers wrap
   adapters; Flatpak requires an independently proven deployment design.

The [development guide](development.md#library-structure) maps the current
modules. Native event, lifecycle and ownership requirements are in the
[adapter contract](adapter-contract.md); implementation and desktop evidence are
in [Fcitx5 validation](fcitx5-validation.md). Platform-specific feasibility and
packaging stages follow the roadmap.

Autocorrection should be a separate optional stage that can be added without
changing the deterministic core. The first implementation need not include a
plugin loader, a dictionary, or a no-op extension framework.

The official [Fcitx5 addon tutorial](https://fcitx-im.org/wiki/Develop_an_simple_input_method)
documents C++ shared-library addons and CMake. The completed local experiment
uses a thin C++ addon and a Rust C ABI; see the [boundary contract](adapter-contract.md#shared-rust-c-abi)
and [build instructions](development.md#build-and-check-the-fcitx5-experiment).
This is the implemented Fcitx5 boundary, not a language choice
for other adapters. An entirely Rust Fcitx5 addon has not been investigated.

The official [Fcitx5 Wayland guide](https://fcitx-im.org/wiki/Using_Fcitx_5_on_Wayland/en)
describes compositor- and application-dependent integration. Test on CachyOS +
KDE Plasma first and record versions. An XWayland application test is useful but
does not establish native Wayland support. Broader support requires more testing.

## Transliteration API

`jong_bangla_core::transliterate(&str) -> String` converts supported phonetic
sequences and ASCII digits. The ASCII capitals `ABCEFHKLMPQVWX` alias their
lowercase forms before matching; all other letters retain case-sensitive behavior.
Matching uses verified priorities; it is not a general longest-match rule across all families.
Consumed keys cannot begin another match. For example, `kkh` wins before `kk`,
but `kk` consumes the first two keys of `kkkh`, giving ক্কখ.

Vowels use context from raw tokens matched within the current call. Copied
Bangla does not supply that context. Unmatched Unicode characters pass through
without Unicode lowercasing or normalization, under the
[v1 case-preservation policy](compatibility.md#unicode-case-preservation-policy);
an unsupported spelling may still contain supported
parts that convert. Calls share no state, and the input is never modified or
retained. Stateful editing is provided separately by the
[composition controller](#composition-controller-api).

Exact expectations live in [fixtures](../tests/fixtures) and regression tests.
The [compatibility guide](compatibility.md) records the pinned reference, Unicode
policy, fixture inventory and links to dated rule investigations. Those historical
records describe their implementation stage, not current coverage limits.
