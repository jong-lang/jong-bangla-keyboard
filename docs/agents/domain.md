# Domain docs

This repository uses a single-context layout.

- Read `GLOSSARY.md` at the repository root before exploring domain terminology.
- Read relevant decision records under `docs/adr/` before proposing a change
  that touches an existing decision.
- Proceed when these files are absent. Create them through the domain-modeling
  workflow when a term or decision is settled.
- Use glossary terms in issues, proposals, and tests. Flag conflicts with an
  existing ADR and identify the decision that needs revisiting.
